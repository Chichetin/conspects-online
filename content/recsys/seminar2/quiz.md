## Лёгкий уровень

### Вопрос 1

Чем схема разбиения last-K отличается от разбиения по времени (time split)?

- [ ] В last-K скрывают одно последнее взаимодействие пользователя, а в time split — все взаимодействия последней недели
- [x] В last-K граница своя у каждого пользователя, а в time split одна дата-граница для всех пользователей
- [ ] В last-K взаимодействия перед разбиением перемешивают, а в time split сортируют по времени
- [ ] В last-K пользователи целиком уходят в тест, а в time split делятся взаимодействия каждого пользователя

**Разбор:** в last-K у каждого пользователя отрезают хвост его собственной последовательности длиной K, когда бы эти взаимодействия ни произошли, поэтому общей даты-границы нет. В time split выбирают одну дату: всё до неё — в обучение, всё после — в валидацию. Скрыть одно последнее взаимодействие — это leave-one-out, а перемешивание — случайное разбиение.

**Где в конспекте:** раздел 1 «Как разбить данные на обучение и валидацию»

### Вопрос 2

В матрице оценок MovieLens заполнено около 4 % клеток. Что означает пустая клетка «пользователь $u$ — фильм $i$»?

- [ ] Пользователю не понравился фильм, поэтому он не стал его оценивать
- [ ] Пользователь оценил фильм ниже своей средней оценки
- [x] Оценка неизвестна: пользователь ещё не взаимодействовал с фильмом
- [ ] Фильма не было в каталоге, когда собирали данные

**Разбор:** пустая клетка — это «неизвестно», а не отрицательное отношение: о подавляющем большинстве пар «пользователь — фильм» мы просто ничего не знаем. Поэтому матрицу хранят в разреженном формате, а не заполняют пустоты нулями или «плохими» оценками.

**Где в конспекте:** раздел 2 «MovieLens: матрица оценок и её особенности»

### Вопрос 3

Популярность фильмов распределена с длинным хвостом. Какую проблему это создаёт для оценки сходства фильмов?

- [ ] Популярные фильмы получают нулевое сходство со всеми остальными
- [x] У редких фильмов очень мало данных, и для них труднее найти похожие
- [ ] Матрицу оценок приходится хранить в плотном формате
- [ ] Сходство приходится считать между пользователями, а не между фильмами

**Разбор:** в хвосте огромное число фильмов с единицами оценок: общих зрителей с другими фильмами у них почти нет, и похожие для них находятся плохо. Вторая проблема длинного хвоста — разнообразие: модель может рекомендовать только популярное и при этом хорошо выглядеть по метрикам.

**Где в конспекте:** раздел 2 «MovieLens: матрица оценок и её особенности»

### Вопрос 4

ItemKNN предсказывает оценку пользователя $u$ фильму $i$. Чьи оценки «голосуют» в этом прогнозе?

- [ ] Оценки фильма $i$ от пользователей, похожих на $u$
- [ ] Оценки фильма $i$ от всех пользователей, усреднённые без весов
- [ ] Скрытые факторы пользователя $u$ и фильма $i$ через скалярное произведение
- [x] Оценки пользователя $u$ фильмам из его истории, похожим на $i$

**Разбор:** в ItemKNN за фильм $i$ голосуют похожие на него фильмы из истории пользователя $u$, вес голоса — сходство $s(i,j)$. Оценки фильма $i$ от похожих пользователей — это UserKNN, а скалярное произведение факторов — матричная факторизация, model-based подход.

**Где в конспекте:** раздел 3 «Memory-based: ItemKNN и UserKNN своими руками»

### Вопрос 5

Соседей фильма *Toy Story 2* ищут по трём мерам сходства. По какой мере в топе оказываются редкие фильмы, у которых с *Toy Story 2* всего 2–6 общих зрителей?

- [ ] По мере Жаккара
- [ ] По косинусному сходству
- [x] По PMI
- [ ] Ни по одной: числитель у всех трёх мер один, поэтому и топ одинаковый

**Разбор:** PMI делит число общих зрителей на произведение популярностей $|U_i|\,|U_j|$ и сравнивает реальное совпадение с ожидаемым при независимом просмотре. Это сильно поднимает редкие фильмы. Числитель $|U_i\cap U_j|$ у всех трёх мер действительно общий, но меры по-разному штрафуют популярность, и у Жаккара и косинуса в топе фильмы с сотнями общих зрителей.

**Где в конспекте:** раздел 3 «Memory-based: ItemKNN и UserKNN своими руками»

### Вопрос 6

Почему матричную факторизацию удобно обучать методом ALS?

- [x] При фиксированных векторах фильмов задача для каждого пользователя — ridge-регрессия с решением в закрытой форме
- [ ] ALS заполняет пустые клетки матрицы средней оценкой пользователя и раскладывает уже полную матрицу
- [ ] ALS делает общий градиентный шаг сразу по $P$ и $Q$, не разделяя их на две группы
- [ ] При фиксированных векторах фильмов векторы пользователей равны их строкам в матрице оценок

**Разбор:** функция потерь содержит произведение $p_u^\top q_i$, и минимизировать сразу по $P$ и $Q$ неудобно. Если зафиксировать $Q$, для каждого пользователя остаётся ridge-регрессия с решением $p_u = (Q_u^\top Q_u + \lambda I)^{-1} Q_u^\top r_u$, затем так же находят $Q$ при фиксированном $P$. Пустые клетки ничем не заполняют: сумма в функции потерь идёт только по известным парам.

**Где в конспекте:** раздел 4 «Model-based: ALS своими руками»

### Вопрос 7

Что такое implicit feedback в датасете KION?

- [ ] Оценки от 1 до 5, которые пользователи ставят видео после просмотра
- [ ] Анкетные данные пользователей: возраст, доход, пол, наличие детей
- [x] Предпочтения, выведенные из поведения: факта просмотра, длительности и доли досмотра
- [ ] Жанры и возрастной рейтинг видео, по которым подбирают похожий контент

**Разбор:** в KION оценок нет. О предпочтениях судят по поведению: смотрел ли пользователь видео, сколько секунд (`total_dur`) и какую долю досмотрел (`watched_pct`). Анкета пользователей и атрибуты видео в датасете есть, но это признаки, а не обратная связь.

**Где в конспекте:** раздел 5 «Implicit feedback на KION: данные, разбиение и метрики»

### Вопрос 8

Что показывает Recall@10?

- [ ] Какую долю каталога модель вообще использует в рекомендациях
- [ ] Насколько непопулярные видео модель включает в топ-10
- [ ] Какая доля из 10 рекомендованных видео оказалась релевантной
- [x] Какую долю релевантных видео из теста модель включила в топ-10

**Разбор:** Recall@10 — доля релевантных видео пользователя (просмотренных на тестовой неделе), которые попали в его топ-10. Доля каталога в выдаче — Coverage, непопулярность рекомендованного — Novelty, а доля релевантных среди 10 рекомендованных — это precision, а не recall.

**Где в конспекте:** раздел 5 «Implicit feedback на KION: данные, разбиение и метрики»

### Вопрос 9

Как устроен бейзлайн Popular?

- [ ] Самые популярные видео среди пользователей, похожих на данного
- [x] Общий для всех список самых популярных видео без уже просмотренного
- [ ] Самые популярные видео, пересортированные под жанры пользователя
- [ ] Случайные видео с вероятностью, пропорциональной их популярности

**Разбор:** Popular — общий для всех список самых просматриваемых видео. Под пользователя он никак не ранжируется, из него только убирается то, что человек уже смотрел. Популярное среди похожих пользователей — это уже персонализация в духе UserKNN.

**Где в конспекте:** раздел 6 «Четыре модели на KION: бейзлайны против персонализации»

### Вопрос 10

Какую роль в двухэтапной модели играет ранкер?

- [ ] Быстро отбирает из всего каталога несколько десятков видео для каждого пользователя
- [ ] Дополняет список кандидатов видео, которые не нашёл ни один генератор
- [x] Получает кандидатов от генераторов и расставляет их по порядку
- [ ] Заново обучает генераторы кандидатов на последней неделе train

**Разбор:** первый этап — генератор кандидатов (кандген): быстрая модель, которая отбирает из каталога несколько десятков видео. Второй этап — ранкер, обычно градиентный бустинг: он только упорядочивает поданных ему кандидатов и ничего нового в список не добавляет.

**Где в конспекте:** раздел 7 «Двухэтапная модель: генераторы кандидатов и CatBoost»

### Вопрос 11

Чем линейная модель SLIM отличается от EASE?

- [ ] SLIM обучает матрицу весов «пользователь – айтем», а EASE — «айтем – айтем»
- [ ] SLIM относится к матричной факторизации, а EASE — к линейным моделям
- [ ] У SLIM обученная матрица весов плотная, а у EASE разреженная
- [x] У SLIM обученная матрица весов разреженная, а у EASE плотная

**Разбор:** обе модели линейные и обучают матрицу весов, которая связывает айтемы между собой. Главное различие — вид этой матрицы: у SLIM большинство весов равно нулю, у EASE матрица плотная. К матричной факторизации относятся ALS и iALS, с которыми SLIM и EASE сравнивали на KION.

**Где в конспекте:** раздел 8 «Линейные модели и вопросы о данных KION»

### Вопрос 12

В обучающей таблице ранкера у пары «пользователь – видео» пусты (NaN) скор и ранг Popular и iALS, а у ItemKNN значения есть. Как это понимать?

- [x] Это видео предложил только ItemKNN, и пустые значения тоже дают бустингу информацию
- [ ] Это ошибка сборки таблицы, такие строки нужно удалить перед обучением
- [ ] Popular и iALS не смогли обучиться на истории этого пользователя
- [ ] Пропуски нужно заполнить значением `"unknown"`, как в категориальных признаках

**Разбор:** задача кандгена — собрать как можно больше элементов из разных источников, поэтому пропуски в колонках генераторов нормальны. Если видео нашёл только ItemKNN, у других генераторов для этой пары нет ни ранга, ни скора, и бустинг видит, что кандидата нашёл один генератор. Значение `"unknown"` нужно только для пропусков в категориальных признаках пользователя и видео: их CatBoost не принимает.

**Где в конспекте:** раздел 7 «Двухэтапная модель: генераторы кандидатов и CatBoost»

## Средний уровень

### Вопрос 1

В индустрии данные чаще всего делят по времени: последние дни — в тест, остальное — в обучение. Какой минус у этой схемы?

- [ ] Модель может «подсмотреть» более поздние действия других пользователей
- [x] Модель обучается не на самых свежих данных: последние дни ушли на проверку
- [ ] Граница у каждого пользователя своя, и результаты разных пользователей несравнимы
- [ ] В тест попадают только пользователи с длинной историей

**Разбор:** последние дни лучше всего отражают текущие интересы пользователей, а при разбиении по времени они уходят в тест. «Подсмотреть» будущее как раз позволяют случайное разбиение и last-K, а своя граница у каждого пользователя — свойство last-K, а не time split.

**Где в конспекте:** раздел 1 «Как разбить данные на обучение и валидацию»

### Вопрос 2

В датасете 2 000 пользователей, 500 фильмов и 50 000 известных оценок. Какая доля клеток матрицы оценок пуста? Ответ — доля от 1.

**Ответ:** 0.95 ± 0.001

**Разбор:** в матрице $2000 \cdot 500 = 1\,000\,000$ клеток. Заполнено $50\,000 / 1\,000\,000 = 0.05$, значит, пусто

$$1 - 0.05 = 0.95.$$

Для сравнения, у MovieLens 1M пусто около 95.7 % клеток.

**Где в конспекте:** раздел 2 «MovieLens: матрица оценок и её особенности»

### Вопрос 3

Пользователь A поставил четыре оценки: 5, 5, 5, 4. Пользователь B — тоже четыре: 2, 3, 3, 4. Оба поставили 4 одному и тому же фильму. После центрирования рейтингов (вычитания средней оценки пользователя) на сколько оценка этого фильма у B больше, чем у A?

**Ответ:** 1.75 ± 0.001

**Разбор:** среднее A: $\bar r_A = 19/4 = 4.75$, среднее B: $\bar r_B = 12/4 = 3$. Центрированные оценки фильма:

$$\tilde r_A = 4 - 4.75 = -0.75,\qquad \tilde r_B = 4 - 3 = 1,\qquad 1 - (-0.75) = 1.75.$$

Одна и та же четвёрка для A — оценка ниже обычной, для B — выше. Центрирование убирает индивидуальную шкалу, и такие оценки становятся сравнимы.

**Где в конспекте:** раздел 3 «Memory-based: ItemKNN и UserKNN своими руками»

### Вопрос 4

ItemKNN выдаёт пользователю топ из семи фильмов, у всех прогноз 5.00. Почему такой топ не стоит считать уверенными рекомендациями?

- [ ] Прогноз 5.00 означает, что модель переобучилась на оценках этого пользователя
- [ ] Без центрирования прогноз не может быть выше средней оценки пользователя
- [ ] В знаменатель попадают неоценённые соседи, и прогноз получается завышен
- [x] Прогноз часто держится на одном оценённом соседе и просто повторяет его оценку 5

**Разбор:** прогноз — взвешенное среднее оценок пользователя по оценённым соседям. Если такой сосед один, прогноз равен его оценке, и 5.00 ничего не говорит об уверенности. Поэтому, кроме самого прогноза, учитывают, на скольких соседях он основан. Переобучиться ItemKNN не может: он memory-based и ничего не обучает. Неоценённые соседи не входят ни в числитель, ни в знаменатель.

**Где в конспекте:** раздел 3 «Memory-based: ItemKNN и UserKNN своими руками»

### Вопрос 5

ALS обучили с $\lambda = 0.05$ и с $\lambda = 5$:

| $\lambda$ | RMSE train | RMSE test |
|:--|:--|:--|
| 0.05 | 0.614 | 1.091 |
| 5 | 0.651 | 0.898 |

Что происходит с моделью при $\lambda = 0.05$?

- [x] Модель переобучается: подгоняется под train и проваливается на тесте
- [ ] Модель недообучается: факторы слишком малы, чтобы объяснить оценки
- [ ] Модель не успела сойтись: при малом $\lambda$ ALS нужны сотни итераций
- [ ] Модель стала точнее: ошибка на train меньше, а тест шумный

**Разбор:** регуляризация $\lambda\left(\|P\|_F^2 + \|Q\|_F^2\right)$ не даёт факторам разрастись. При слишком маленьком $\lambda$ ошибка на train самая низкая, а на тесте самая высокая — это переобучение. Недообучение видно при слишком большом $\lambda$ (при $\lambda = 50$ ошибка высокая и на train, и на test). Со сходимостью проблем нет: ALS сходится уже ко второй итерации.

**Где в конспекте:** раздел 4 «Model-based: ALS своими руками»

### Вопрос 6

Модель предсказала оценки для пяти скрытых пар. Настоящие оценки: 5, 3, 4, 2, 4. Прогнозы: 3, 4, 4, 2, 4. Найдите RMSE.

**Ответ:** 1 ± 0

**Разбор:** ошибки $r_{ui} - \hat r_{ui}$: 2, −1, 0, 0, 0. Квадраты: 4, 1, 0, 0, 0.

$$\mathrm{RMSE} = \sqrt{\frac{4 + 1 + 0 + 0 + 0}{5}} = \sqrt{1} = 1.$$

Средняя абсолютная ошибка здесь была бы $3/5 = 0.6$: RMSE сильнее наказывает за крупный промах на две звезды.

**Где в конспекте:** раздел 4 «Model-based: ALS своими руками»

### Вопрос 7

В KION каждому просмотру от 300 секунд дали вес 1. Что получится, если обучить на этих данных обычный ALS, который минимизирует ошибку только на известных парах?

- [ ] ALS выучит, что все непросмотренные видео пользователю не нравятся
- [x] Модель выучит константу: на всех известных парах правильный ответ один и тот же
- [ ] Модель переобучится на пользователей с самой длинной историей
- [ ] Модель начнёт предсказывать долю досмотра вместо факта просмотра

**Разбор:** все известные пары — «единицы», и функции потерь по ним достаточно, чтобы модель везде отвечала 1. Непросмотренные пары в такую функцию потерь не входят вовсе, поэтому про них модель ничего не выучит. Отсюда iALS: он смотрит на все пары и взвешивает их уверенностью.

**Где в конспекте:** раздел 5 «Implicit feedback на KION: данные, разбиение и метрики»

### Вопрос 8

KION разбили по времени: последние 7 дней — в тест. В тесте оставили только пользователей, которые есть и в train. Зачем?

- [ ] Чтобы в тест не попали просмотры короче 300 секунд
- [ ] Чтобы модели не рекомендовали уже просмотренные видео
- [x] О новых пользователях у моделей без признаков нет никакой информации
- [ ] Чтобы число пользователей в train и в test совпадало

**Разбор:** модели вроде Popular, ItemKNN и iALS опираются только на историю взаимодействий. Для пользователя, которого не было в train, им не на что опереться, и такие пользователи только исказили бы сравнение. Короткие просмотры отсекает фильтр по 300 секундам, а просмотренное убирает параметр `filter_viewed=True`.

**Где в конспекте:** раздел 5 «Implicit feedback на KION: данные, разбиение и метрики»

### Вопрос 9

У бейзлайна Random на KION Coverage@10 = 1 и самая высокая Novelty, а Recall@10 = 0.0007. Какие выводы из этих чисел верны?

- [ ] Random даёт самую разнообразную выдачу, его стоит выкатывать вместе с персональной моделью
- [x] Coverage и Novelty описывают характер выдачи, а не качество рекомендаций
- [ ] Coverage 1 значит, что Random нашёл все релевантные видео, а Recall занижен фильтром

- [ ] У пользователей с короткой историей в тестовой неделе больше релевантных видео

### Вопрос 11

Откуда берутся метки 1 и 0 для CatBoostClassifier на втором этапе двухэтапной модели?

- [x] Внутри train отрезают последнюю неделю; кандидат, просмотренный на ней, получает метку 1

### Вопрос 1

Три генератора кандидатов выдали объединённый список, в среднем около 45 видео на пользователя. Для четырёх тестовых пользователей известно:

| Пользователь | Релевантных видео в тестовой неделе | Из них в объединённых кандидатах |
|:--|--:|--:|
| A | 4 | 3 |
| B | 2 | 1 |
| C | 4 | 1 |
| D | 1 | 1 |

Ранкер выбирает топ-10 из этих кандидатов. Какой наибольший средний Recall@10 по этим четырём пользователям может дать любой ранкер?

**Ответ:** 0.625 ± 0.001

**Разбор:** ранкер только переупорядочивает кандидатов, поэтому в лучшем случае поднимет в топ-10 все релевантные видео из объединённого списка (их у каждого не больше 10). Recall считается по каждому пользователю и усредняется:

$$\frac{3/4 + 1/2 + 1/4 + 1/1}{4} = \frac{0.75 + 0.5 + 0.25 + 1}{4} = 0.625.$$

Это потолок второго этапа. Если сложить попадания всех пользователей и разделить на всех релевантных ($6/11$), получится не та метрика: по ней не усредняют по пользователям.

В двухэтапной модели на KION важность признаков CatBoost такая: скор Popular около 27 %, год выпуска около 16 %, скор ItemKNN около 12.5 %, ранг ItemKNN около 8 %; пол, возраст и доход — почти ноль. Какие выводы верны?

- [x] Популярное «просачивается» в ранкер: сильнее всего модель опирается на популярность
- [ ] Генераторы ItemKNN и iALS можно убрать: ранкеру хватает скора Popular
- [x] С перекосом в популярное борются, например, андерсэмплингом популярных айтемов при обучении
- [ ] Раз признаки пользователя не важны, двухэтапная модель вообще не персонализирована
- [x] Анкетные признаки пользователя (пол, возраст, доход) почти не влияют на предсказания ранкера

**Разбор:** лидерство скора Popular — тот же эффект, что и в сравнении моделей: популярное просачивается везде, и с этим борются, например, андерсэмплингом. ### Вопрос 3

В двухэтапной модели CatBoostClassifier заменили на CatBoostRanker с `loss_function="YetiRank"`. Какие утверждения верны?

- [ ] Ранкер начнёт находить видео, которых нет среди кандидатов генераторов
- [x] Модель учится упорядочивать кандидатов внутри каждого пользователя, а не оценивать пары по отдельности
- [ ] Классификатор уже учитывал конкуренцию кандидатов одного пользователя, поэтому разницы не будет
- [x] Классификатор и ранкер на втором этапе сравнивают в первую очередь по NDCG
- [ ] YetiRank обучается заметно дольше классификатора, поэтому его оставляют для финальной модели

### Вопрос 8

В iALS слагаемое ошибки для пары $(u, i)$ равно $c_{ui}\,(p_{ui} - p_u^\top q_i)^2$, где $p_{ui} = 1$, если пользователь смотрел видео, иначе 0, а $c_{ui} = 1 + \alpha$ для просмотренных пар и 1 для остальных.
